# User stories — Гильдия Комфорта

Все пользовательские истории **реализованной** функциональности. Каждая
история сопровождается критериями приёмки, отражающими фактическое
поведение кода (включая ограничения), и ссылкой на файл, где она
реализована.

Что здесь **не описано**: гипотетические и планируемые возможности. Если
истории нет в этом документе — этого нет и в приложении. Перечень
осознанно отсутствующей функциональности — в конце документа.

Обозначения ролей: **А** — администратор, **М** — монтажник,
**З** — заказчик, **—** — доступно без входа в систему.

## A. Доступ в систему

### US-01 · Самостоятельная регистрация — **М**, **З**

**Как** новый монтажник или заказчик, **я хочу** зарегистрироваться сам,
**чтобы** начать работать без ожидания, пока меня заведёт администратор.

Критерии приёмки:
- Форма на `/register` запрашивает: роль, ФИО, e-mail, телефон
  (необязательно), пароль.
- В выборе роли доступны только «Монтажник» и «Заказчик». **Роль
  «Администратор» зарегистрировать нельзя** — она создаётся только
  сид-скриптом.
- Пароль — не короче 6 символов, ФИО — не короче 2 символов, e-mail
  приводится к нижнему регистру и проверяется на формат.
- Повторная регистрация на занятый e-mail отклоняется с сообщением
  «Пользователь с таким e-mail уже зарегистрирован».
- После успешной регистрации пользователь сразу залогинен и попадает в
  свой кабинет — повторный вход не требуется.

Реализовано: `src/app/register/page.tsx`, `src/app/register/RegisterForm.tsx`,
`src/app/actions/auth.ts` (`registerAction`, схема с ограничением роли —
строка 64).

### US-02 · Вход по e-mail и паролю — **А**, **М**, **З**

**Как** пользователь системы, **я хочу** войти по e-mail и паролю,
**чтобы** получить доступ к своим данным.

Критерии приёмки:
- Форма на `/login` запрашивает e-mail и пароль.
- При неверных данных показывается единое сообщение «Неверный e-mail или
  пароль» — по нему нельзя определить, существует ли такой пользователь.
- Пароли хранятся в виде bcrypt-хэша, в открытом виде не хранятся нигде.
- Сессия — JWT в httpOnly-cookie `goc_session` со сроком жизни 7 дней;
  из JavaScript браузера cookie недоступна.
- После входа пользователь попадает в кабинет своей роли (см. US-04).

Реализовано: `src/app/login/page.tsx`, `src/app/login/LoginForm.tsx`,
`src/app/actions/auth.ts` (`loginAction`), `src/lib/auth.ts`.

### US-03 · Выход из системы — **А**, **М**, **З**

**Как** пользователь, **я хочу** выйти из системы, **чтобы** никто не мог
воспользоваться моей сессией на общем устройстве.

Критерии приёмки:
- Кнопка «Выйти» доступна в верхней панели на каждой странице любого
  кабинета.
- Cookie сессии удаляется, происходит переход на `/login`.

Реализовано: `src/components/TopBar.tsx`, `src/app/actions/auth.ts`
(`logoutAction`).

### US-04 · Автоматический переход в кабинет своей роли — **А**, **М**, **З**

**Как** пользователь, **я хочу** после входа сразу оказаться на нужной мне
странице, **чтобы** не искать свой раздел вручную.

Критерии приёмки:
- Администратор попадает на `/admin`, монтажник — на `/installer`,
  заказчик — на `/customer`.
- Тот же переход происходит при открытии корня сайта `/` уже вошедшим
  пользователем.
- Уже вошедший пользователь, открывший `/login` или `/register`,
  перенаправляется в свой кабинет.

Реализовано: `src/lib/session.ts` (`homeForRole`), `src/app/page.tsx`,
`src/proxy.ts`.

### US-05 · Изоляция кабинетов по ролям — **А**, **М**, **З**

**Как** владелец бизнеса, **я хочу**, чтобы пользователь не мог открыть
раздел чужой роли, **чтобы** коммерческие и личные данные не утекали.

Критерии приёмки:
- Попытка открыть страницу чужой роли перенаправляет пользователя в его
  собственный кабинет.
- Неавторизованный пользователь на защищённой странице отправляется на
  `/login`.
- Проверка выполняется в трёх местах независимо: в layout'е каждого
  кабинета, на самой странице и внутри каждого серверного действия.
  `src/proxy.ts` даёт лишь быстрый оптимистичный редирект и **не является
  источником истины** по авторизации.
- Данные всегда выбираются с фильтром по владению: монтажник видит только
  объекты, на которые назначен; заказчик — только свои объекты.

Реализовано: `src/lib/session.ts` (`requireRole`), `src/app/admin/layout.tsx`,
`src/app/installer/layout.tsx`, `src/app/customer/layout.tsx`,
`src/proxy.ts`.

## B. Справочники и технологические карты

### US-06 · Завести материал — **А**

**Как** администратор, **я хочу** добавить материал в общий справочник,
**чтобы** использовать его в техкартах и на складах объектов.

Критерии приёмки:
- Форма запрашивает название и единицу измерения (шт, м, кг и т. п.).
- Оба поля обязательны.
- Материал сразу доступен для техкарт и для оприходования на склады.
- Уникальность названия не проверяется — одноимённые материалы завести
  можно (это осознанное упрощение MVP).

Реализовано: `src/app/admin/materials/page.tsx`,
`src/app/actions/materials.ts`.

### US-07 · Смотреть справочник материалов — **А**

**Как** администратор, **я хочу** видеть список всех материалов,
**чтобы** понимать, что уже заведено, и не плодить дубли.

Критерии приёмки:
- Таблица со всеми материалами и их единицами измерения.
- Сид-скрипт при первом запуске заводит 10 базовых позиций (саморезы,
  гайки, болты, дюбели, кабель, гофра, воздуховод, хомуты, фреон).

Реализовано: `src/app/admin/materials/page.tsx`, `prisma/seed.ts`.

### US-08 · Завести операцию — **А**

**Как** администратор, **я хочу** описать типовую операцию (например,
«Монтаж воздуховода d125»), **чтобы** ставить на её основе задачи на
любых объектах.

Критерии приёмки:
- Форма запрашивает название (обязательно), категорию, описание и
  инструменты.
- Инструменты вводятся одной строкой через запятую и сохраняются списком;
  пустые значения отбрасываются.
- Операция сразу доступна при создании задач.

Реализовано: `src/app/admin/operations/page.tsx`,
`src/app/actions/operations.ts` (`createOperationAction`).

### US-09 · Смотреть справочник операций — **А**

**Как** администратор, **я хочу** видеть все операции со сводкой,
**чтобы** понимать, у каких операций уже заполнена техкарта.

Критерии приёмки:
- Таблица операций с категорией, количеством позиций в техкарте и
  количеством задач, созданных на основе операции.
- Название операции — ссылка на её техкарту.

Реализовано: `src/app/admin/operations/page.tsx`.

### US-10 · Задать норму расхода материала в техкарте — **А**

**Как** администратор, **я хочу** указать, сколько какого материала
уходит на операцию, **чтобы** монтажнику при завершении задачи
подставлялась норма, а не пустое поле.

Критерии приёмки:
- Форма на странице операции: выбор материала + количество (больше нуля,
  до 3 знаков после запятой).
- Повторное добавление того же материала **перезаписывает** норму, а не
  суммирует её.
- Норма подставляется по умолчанию в форму завершения задачи (US-29).

Реализовано: `src/app/admin/operations/[operationId]/page.tsx`,
`src/app/actions/operations.ts` (`addTechCardMaterialAction`).

### US-11 · Убрать материал из техкарты — **А**

**Как** администратор, **я хочу** удалить лишний материал из техкарты,
**чтобы** исправить ошибку при заполнении.

Критерии приёмки:
- Кнопка «Удалить» в строке материала техкарты.
- Уже созданные задачи и уже сделанные списания не затрагиваются —
  удаление влияет только на подстановку в будущих задачах.

Реализовано: `src/app/admin/operations/[operationId]/page.tsx`,
`src/app/actions/operations.ts` (`removeTechCardMaterialAction`).

## C. Запуск объекта

### US-12 · Создать объект — **А**

**Как** администратор, **я хочу** завести объект монтажа, **чтобы**
начать планировать по нему работы.

Критерии приёмки:
- Форма запрашивает название (от 2 символов) и адрес (от 3 символов).
- **Склад объекта создаётся автоматически** вместе с объектом — отдельного
  действия не требуется.
- Объект создаётся в статусе «Активен».
- Заказчик выбирается из списка или не указывается вовсе (см. US-13).

Реализовано: `src/app/admin/page.tsx`, `src/app/actions/sites.ts`
(`createSiteAction`, автосоздание склада — строка 35).

### US-13 · Создать объект без заказчика и прикрепить его позже — **А**

**Как** администратор, **я хочу** завести объект до того, как заказчик
зарегистрировался, **чтобы** не откладывать планирование работ.

Критерии приёмки:
- В форме создания объекта есть вариант «— без заказчика (можно прикрепить
  позже) —».
- Если заказчиков в системе ещё нет, подсказка объясняет, что объект можно
  создать без заказчика.
- На странице объекта без заказчика появляется блок «Прикрепить заказчика»
  с выбором из зарегистрированных заказчиков. После прикрепления блок
  исчезает.
- В списке объектов у объекта без заказчика отображается «не назначен».

Реализовано: `src/app/admin/page.tsx`,
`src/app/admin/sites/[siteId]/page.tsx`, `src/app/actions/sites.ts`
(`assignCustomerAction`).

### US-14 · Назначить монтажника на объект — **А**

**Как** администратор, **я хочу** назначить монтажников на объект,
**чтобы** они видели его в своём кабинете и могли брать задачи.

Критерии приёмки:
- Выбор из монтажников, ещё не назначенных на этот объект.
- Повторное назначение того же монтажника безопасно — дубль не создаётся.
- Только после назначения монтажник видит объект (US-23) и может взять
  задачу (US-24).

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`,
`src/app/actions/sites.ts` (`assignInstallerAction`).

### US-15 · Снять монтажника с объекта — **А**

**Как** администратор, **я хочу** снять монтажника с объекта, **чтобы**
перераспределить людей между объектами.

Критерии приёмки:
- Кнопка «Снять» в строке монтажника.
- Монтажник теряет доступ к объекту и его задачам.
- Задачи, уже закреплённые за этим монтажником, **остаются закреплёнными
  за ним** — автоматически они не освобождаются.

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`,
`src/app/actions/sites.ts` (`unassignInstallerAction`).

### US-42 · Назначить бригадира на объекте — **А**

**Как** администратор, **я хочу** назначить одного из монтажников
бригадиром на объекте, **чтобы** он вёл табель за всю бригаду и остальным
не приходилось заполнять его самим.

Критерии приёмки:
- В строке каждого назначенного монтажника — кнопка «Сделать бригадиром»
  / «Снять бригадирство», у текущего бригадира стоит пометка.
- Бригадирство привязано к **объекту**: на одном объекте монтажник может
  быть бригадиром, на другом — обычным исполнителем.
- Бригадиров на объекте может быть несколько — ограничения нет.
- Сразу после назначения у монтажника в табеле появляется выбор
  монтажника (US-34); после снятия — исчезает, и сервер перестаёт
  принимать от него записи за других.

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`,
`src/app/actions/sites.ts` (`setForemanAction`).

### US-16 · Менять статус объекта — **А**

**Как** администратор, **я хочу** отметить объект как приостановленный
или завершённый, **чтобы** отражать реальное положение дел.

Критерии приёмки:
- Три кнопки: «Активен», «Приостановлен», «Завершён»; текущий статус
  неактивен.
- Переход возможен между любыми статусами в любом порядке.
- Статус отображается бейджем в списке объектов.

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`,
`src/app/actions/sites.ts` (`updateSiteStatusAction`).

### US-17 · Видеть все объекты с прогрессом — **А**

**Как** администратор, **я хочу** видеть все объекты на одном экране,
**чтобы** быстро оценить, где что происходит.

Критерии приёмки:
- Таблица: объект (с адресом), заказчик, статус, прогресс.
- Прогресс — доля задач в статусе «Выполнена» от всех задач объекта,
  полосой и в процентах. У объекта без задач — пометка «нет задач».
- Объекты отсортированы от новых к старым.

Реализовано: `src/app/admin/page.tsx`.

## D. Планирование работ

### US-18 · Создать подпроект — **А**

**Как** администратор, **я хочу** разделить объект на подпроекты
(вентиляция, электрика, автоматика, кондиционирование), **чтобы**
группировать задачи по направлениям.

Критерии приёмки:
- Форма на странице объекта запрашивает название подпроекта (от 2
  символов).
- Подпроекты выводятся списком со сводкой «N из M задач выполнено».

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`,
`src/app/actions/subprojects.ts`.

### US-19 · Создать задачу на основе операции — **А**

**Как** администратор, **я хочу** поставить задачу в подпроекте,
**чтобы** монтажник мог взять её в работу.

Критерии приёмки:
- Форма запрашивает операцию из справочника (обязательно), название
  задачи (от 2 символов) и описание (необязательно).
- Задача создаётся в статусе «Свободна» и **без исполнителя**.
- Назначить задачу конкретному монтажнику администратор не может —
  монтажник берёт её сам (US-24).
- Техкарта выбранной операции определяет, какие материалы монтажник будет
  списывать при завершении.

Реализовано: `src/app/admin/sites/[siteId]/sub-projects/[subProjectId]/page.tsx`,
`src/app/actions/tasks.ts` (`createTaskAction`).

### US-20 · Видеть задачи подпроекта — **А**

**Как** администратор, **я хочу** видеть все задачи подпроекта,
**чтобы** контролировать, что взято в работу и кем.

Критерии приёмки:
- Таблица: название задачи, операция, статус (цветной бейдж), монтажник
  (или «—», если задача свободна).
- Страница недоступна, если подпроект принадлежит другому объекту, чем
  указан в адресе.

Реализовано: `src/app/admin/sites/[siteId]/sub-projects/[subProjectId]/page.tsx`.

## E. Снабжение объекта

### US-21 · Оприходовать материал на склад объекта — **А**

**Как** администратор, **я хочу** отразить поступление материала на
объект, **чтобы** монтажники могли списывать его при выполнении задач.

Критерии приёмки:
- Форма на странице объекта: материал, количество (больше нуля),
  комментарий (необязательно).
- Остаток увеличивается, и одновременно создаётся запись движения типа
  «Приход» с указанием, кто и когда оприходовал. Обе операции — в одной
  транзакции.
- Приходовать материалы может **только администратор**; монтажник — нет.

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`,
`src/app/actions/warehouse.ts`.

### US-22 · Видеть остатки на складе объекта — **А**

**Как** администратор, **я хочу** видеть текущие остатки по объекту,
**чтобы** вовремя довезти материал.

Критерии приёмки:
- Таблица «материал — остаток — единица» на странице объекта.
- Пока приходов не было — «Остатков пока нет».

Реализовано: `src/app/admin/sites/[siteId]/page.tsx`.

## F. Выполнение работ

### US-23 · Видеть свои объекты — **М**

**Как** монтажник, **я хочу** видеть только те объекты, на которые меня
назначили, **чтобы** не отвлекаться на чужие.

Критерии приёмки:
- Список объектов, где для меня есть назначение (US-14).
- По каждому объекту — счётчики «Свободных задач» и «Закреплено за мной».
- Объекты, на которые я не назначен, не видны и недоступны по прямой
  ссылке.

Реализовано: `src/app/installer/page.tsx`,
`src/app/installer/sites/[siteId]/page.tsx`.

### US-24 · Взять свободную задачу в работу — **М**

**Как** монтажник, **я хочу** сам взять свободную задачу, **чтобы**
начать работу без ожидания распределения.

Критерии приёмки:
- Кнопка «Взять в работу» показывается только у задач в статусе
  «Свободна».
- Задача переходит в статус «Назначена», закрепляется за мной,
  фиксируется время назначения.
- Если задачу уже взял кто-то другой — ошибка «Задача уже закреплена за
  кем-то».
- Взять задачу можно только на объекте, на который я назначен, иначе —
  «Вы не назначены на этот объект».
- Переход записывается в историю задачи.

Реализовано: `src/app/installer/sites/[siteId]/page.tsx`,
`src/app/actions/tasks.ts` (`takeTaskAction`).

### US-25 · Начать выполнение задачи — **М**

**Как** монтажник, **я хочу** отметить начало работы, **чтобы** было
видно, что задача в работе, а не просто закреплена.

Критерии приёмки:
- Кнопка «Выполнить (начать работу)» доступна только в статусе
  «Назначена».
- Статус меняется на «В работе», фиксируется время старта.
- Повторный старт после паузы **не перезаписывает** первоначальное время
  начала.
- Чужую задачу открыть или начать нельзя.

Реализовано: `src/app/installer/tasks/[taskId]/page.tsx`,
`src/app/actions/tasks.ts` (`startTaskAction`).

### US-26 · Поставить задачу на паузу с причиной — **М**

**Как** монтажник, **я хочу** приостановить задачу и объяснить почему,
**чтобы** у администратора была понятная картина по срокам.

Критерии приёмки:
- Доступно только из статуса «В работе».
- **Причина обязательна** (не короче 3 символов) — без неё действие
  отклоняется.
- Статус меняется на «Пауза», причина сохраняется в истории задачи и
  показывается на карточке задачи.

Реализовано: `src/app/installer/tasks/[taskId]/page.tsx`,
`src/app/actions/tasks.ts` (`pauseTaskAction`).

### US-27 · Заблокировать задачу с причиной — **М**

**Как** монтажник, **я хочу** отметить, что задача заблокирована внешней
причиной (нет материала, не готово смежниками), **чтобы** это было видно
и не считалось моим простоем.

Критерии приёмки:
- Доступно только из статуса «В работе».
- **Причина обязательна** (не короче 3 символов).
- Статус меняется на «Заблокирована», причина сохраняется в истории.

Реализовано: `src/app/installer/tasks/[taskId]/page.tsx`,
`src/app/actions/tasks.ts` (`blockTaskAction`).

### US-28 · Возобновить задачу — **М**

**Как** монтажник, **я хочу** вернуть задачу в работу после паузы или
снятия блокировки, **чтобы** продолжить выполнение.

Критерии приёмки:
- Кнопка «Возобновить» доступна в статусах «Пауза» и «Заблокирована».
- Статус возвращается в «В работе»; причина при возобновлении **не
  требуется**.
- Переход записывается в историю.

Реализовано: `src/app/installer/tasks/[taskId]/page.tsx`,
`src/app/actions/tasks.ts` (`resumeTaskAction`).

### US-29 · Завершить задачу со списанием материалов — **М**

**Как** монтажник, **я хочу** отчитаться о фактическом расходе материалов
при завершении задачи, **чтобы** склад объекта отражал реальные остатки.

Критерии приёмки:
- Доступно только из статуса «В работе».
- Форма показывает по одному полю на каждый материал техкарты операции;
  количество **предзаполнено нормой** из техкарты и может быть изменено по
  факту. Значение 0 означает, что материал не расходовался.
- Если в техкарте операции материалов нет — форма это сообщает, и задача
  завершается без списания.
- Остатки уменьшаются, по каждому материалу создаётся запись движения
  типа «Расход», привязанная к этой задаче и ко мне.
- **Если хотя бы одного материала не хватает на складе** — операция
  отклоняется целиком: не списывается ничего, задача остаётся «В работе»,
  показывается сообщение вида «Недостаточно материала «Гайка М8» на
  складе: доступно 5, требуется 12».
- При успехе задача переходит в статус «На проверке», фиксируется время
  завершения, переход попадает в историю.

Реализовано: `src/app/installer/tasks/[taskId]/page.tsx`,
`src/app/actions/tasks.ts` (`finishTaskAction`, транзакция со списанием —
строки 205–243).

### US-30 · Видеть карточку задачи с инструментами и историей — **М**

**Как** монтажник, **я хочу** видеть, что за работа, каким инструментом и
что с задачей уже происходило, **чтобы** не переспрашивать.

Критерии приёмки:
- Карточка показывает название, подпроект, операцию, статус, описание.
- Список инструментов из операции — если они заданы.
- История всех переходов: когда, из какого статуса в какой, причина, кто
  выполнил — от новых к старым.
- Открыть можно только задачу, закреплённую за мной.

Реализовано: `src/app/installer/tasks/[taskId]/page.tsx`.

## H. Учёт времени

### US-34 · Внести отработанные часы — **М**

**Как** монтажник, **я хочу** записать отработанные часы, **чтобы** они
попали в табель для расчёта.

Критерии приёмки:
- Экран рассчитан на телефон: сегмент «Ввод / Данные», быстрые кнопки
  «Вчера / Сегодня», чипы последних объектов, тач-цели не меньше 44px.
- Форма: монтажник, дата (по умолчанию сегодня), часы, объект
  (необязательно), комментарий.
- Часы — больше нуля и **не больше 24**, шаг 0.5.
- В выборе объекта — только те объекты, на которые я назначен.
- Обычный монтажник видит своё имя неизменяемой строкой — записать часы
  на другого он не может.
- Бригадир (US-42) видит выбор монтажника и может внести часы за
  монтажника своей бригады. Выбор монтажника и объекта остаётся
  согласованной парой: при смене одного второй подстраивается.
- **Сервер проверяет права заново, независимо от формы.** При записи за
  другого монтажника: объект обязателен («Выберите объект, чтобы внести
  часы за другого монтажника»), автор должен быть бригадиром именно на
  этом объекте («Вы не бригадир на этом объекте»), целевой монтажник —
  назначен на него («Этот монтажник не назначен на объект»).

Реализовано: `src/app/installer/timesheet/page.tsx`,
`src/components/TimesheetForm.tsx`, `src/app/actions/timesheet.ts`.

### US-35 · Видеть свои записи табеля — **М**

**Как** монтажник, **я хочу** видеть свой табель, **чтобы** проверить,
всё ли я внёс.

Критерии приёмки:
- Вкладка «Данные»: дата, объект, часы, комментарий — от новых дат к
  старым, последние 100 записей.
- Обычный монтажник видит **только свои** записи; чужие недоступны.
- Бригадир дополнительно видит записи бригады по объектам, где он
  бригадир — он же их и вносит. Чужое имя в такой записи подписано.

Реализовано: `src/app/installer/timesheet/page.tsx`.

### US-36 · Видеть сводный табель по всем монтажникам — **А**

**Как** администратор, **я хочу** видеть табель всех монтажников,

Критерии приёмки:

## Чего в текущей версии нет

Осознанно не реализовано в MVP. Перечислено, чтобы документ не создавал
ложных ожиданий:

| Возможность | Комментарий |
| --- | --- |
| Смена пароля из интерфейса | Экрана нет. Пароль администратора меняется через повторный сид с другими переменными окружения. |
| Назначение задачи конкретному монтажнику | Только самозахват свободной задачи монтажником (US-24). |
| Отказ от взятой задачи | Обратного перехода «Назначена → Свободна» нет ни у монтажника, ни у администратора. |
| Возврат задачи из статуса «Выполнена» | Статус конечный. |
| Редактирование и удаление справочников | Материалы, операции, объекты, подпроекты и задачи только создаются. Удаляются лишь строки техкарты (US-11) и назначения монтажников (US-15). |
| Возврат материалов на склад | Списание при завершении задачи необратимо; корректировка возможна только новым приходом. |
| Кабинет финансов у монтажника | Данные есть в модели, интерфейса нет (US-38). |
| Фотографии и файлы с объектов | Файлового хранилища в MVP нет. |
| Акты выполненных работ, выгрузки, уведомления | Не реализовано. |
| Row Level Security на уровне PostgreSQL | Авторизация реализована на уровне приложения; обоснование — в [README.md](../README.md). |
