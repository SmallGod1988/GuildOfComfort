Что это

Учёт монтажных работ для своей бригады: автоматика, вентиляция, электрика, кондиционирование. Главное отличие от таблицы в Excel — готовность считается в деньгах, а не по числу закрытых строк.

КтоЧто былоЧто стало
Прораб КП в Excel, факт в голове и в переписке; «сколько сделано» — на глаз Освоение в рублях и процентах, считается само
Монтажник Отчитывается словами, объём вспоминает задним числом Отмечает объём с телефона по ходу работы
Заказчик Спрашивает статус в мессенджере Смотрит готовность по блокам сам

Роли

Три роли, у каждой свой кабинет. Кабинет чужой роли открыть нельзя.

РольКабинетЧто делает
Администратор /admin Заводит объекты и работы, принимает выполненное, ведёт справочники, склад и взаиморасчёты, увольняет и возвращает людей
Монтажник /installer Берёт свободные задачи на своих объектах, отмечает объём, ведёт табель. Бригадир — ещё и за бригаду
Заказчик /customer Смотрит ход работ по своим объектам. Внутренней кухни и ФИО не видит
Администратор создаётся сид-скриптом при развёртывании. Монтажники и заказчики регистрируются сами на /register — или им заводят доступы скриптом prisma/setup-team.ts, который печатает логины с паролями для раздачи.

Как устроен объект

Работы на объекте раскладываются деревом. Раньше оно было плоским, теперь повторяет структуру коммерческого предложения.

Гибкая задача — та, где подзадачи заводит сам монтажник по ходу дела: проложил участок лотка — записал участок и метры. Заранее их не спланировать.

Готовность по деньгам

Ключевая идея. Вес позиции — это её доля в сумме КП, а не «одна задача из двадцати». 

84 000 ₽ ÷ 231 525 ₽ = 36,3 %   ← прокладка кабеля одна весит больше трети
18 900 ₽ ÷ 231 525 ₽ =  8,2 %   ← монтаж лотка
     0 ₽ ÷ 231 525 ₽ =  0,0 %   ← сдача заказчику: включена в стоимость

Поэтому закрытая мелочь не двигает шкалу, а закрытая прокладка кабеля двигает сразу на треть. Готовность показывает реальное освоение денег.

Как считается

Снизу вверх. У листа дерева — доля выполненного объёма; у узла — взвешенная сумма детей:

ПравилоКогда применяется
Явный весЭтапы внутри задачи: навеска щита 15 %, расключение 85 %
Деньги КППозиции: доля стоимости в итоге
Плановый объёмЕсли ни весов, ни сумм нет
ПоровнуЕсли и объёмов нет
Готовность нигде не хранится — считается при каждом показе. Дерево одного объекта это сотня строк, пересчёт дешевле, чем поддерживать сохранённое поле в согласованном виде.

Блоки работ

Блок — то, что выдаётся монтажникам как единица очерёдности. Дереву задач он не соответствует: один блок может собрать несколько позиций КП, а одна позиция — разделиться между блоками по этапам. 

Монтаж гильз      → блок Б2   ┐
                              │ между ними прокладывают кабель
Зачеканка проходов → блок Б5  ┘   — это одна позиция КП, но два блока

Четыре состояния

СостояниеКогда
ДоступенПредшественники набрали порог — можно выдавать
ОжидаетПредшественники ещё не готовы. Видно, каких именно ждёт
ЗаблокированУказана причина руками: нет материалов, доступа, стройготовности
ВыполненВсе задачи блока закрыты

Порог — доля готовности предшественников, при которой блок открывается. По умолчанию 100 %. Снижают, чтобы вести работы параллельно: при 60 % маркировку можно начинать, не дожидаясь последнего метра кабеля.

Ручная причина блокировки перебивает расчёт: такой блок красный, даже если все предшественники закрыты. И попадает в отчёт заказчику.

Жизнь задачи

Задачу берёт сам монтажник, и только на объекте, куда он назначен. Назначить задачу конкретному человеку администратор не может. Отказаться от взятой — тоже нельзя.

Загрузка книги КП

Экран «Загрузка КП» в кабинете администратора. Выбираете объект или заводите новый, прикладываете .xlsx — и весь состав работ появляется за раз. С телефона это обычный выбор файла.

Лист книгиЧто берётся
КППозиции, единицы, количество, цены, суммы и ИТОГО
Задачи монтажаДерево по номерам «2.1.1», разделы, системы, объёмы, привязка к блокам
ЗависимостиБлоки работ, их предшественники и пороги. Необязателен

Пустые заготовки подзадач («Подзадача 1.1 — заполняется монтажником») пропускаются: их заводит монтажник по факту.

Повторная загрузка ничего не переписывает — создаётся ещё один состав работ рядом. Уже отмеченные объёмы не теряются.

Табель

Монтажник вносит часы за себя. Бригадир — ещё и за бригаду, но только на том объекте, где он бригадир, и только за тех, кто на этот объект назначен.

Бригадирство привязано к объекту: на одном человек ведёт табель за всех, на другом — обычный исполнитель.

Выгрузка в Excel

Администратор задаёт период и получает книгу по образцу таблицы компании: семь листов, сводки и отчёты — живыми формулами, а не посчитанными числами, поэтому дописанные вручную строки пересчитываются сами.

Форма принимает только часы больше нуля. Нулей и минусов (прогул, штраф) внести нельзя, хотя в реальном табеле компании они встречаются. Такие строки заводятся только скриптом импорта, и отредактировать их потом через интерфейс не выйдет.

Склад и техкарты

У каждого объекта свой склад — заводится вместе с объектом. Администратор оформляет приход, списание происходит само при завершении задачи.

Техкарта операции задаёт норму расхода на одну единицу работ, не на всю задачу. Плановый расход считается умножением: норма × объём задачи.

При завершении задачи состав формы проверяется заново: материал не из техкарты списать нельзя, и остатка должно хватать. Списание и движение пишутся одной операцией — расхождения между «сколько лежит» и «откуда взялось» не возникает.
Списание необратимо. Возврата материалов на склад нет: если задачу вернули с проверки, материалы остаются израсходованными — они уже на объекте. Корректировка возможна только новым приходом.

Взаиморасчёты

Администратор вносит начисления и выплаты по участникам. Баланс = начислено − выплачено.

Записи приватные: их видит администратор и сам участник — только свои. Кабинета финансов у монтажника пока нет: данные в модели есть, экрана нет.

Доступ

Пароли хранятся хешем (bcrypt), сессия — подписанный токен в защищённой куке на 7 дней.

Почему увольнение срабатывает сразу

Токен живёт неделю и об увольнении не знает. Поэтому проверка роли по куке ничего не решает: каждая страница и каждое действие заново читают пользователя из базы. Уволенного выкидывает на вход при первом же обращении, а не через неделю.

Восстановление пароля

Ссылка на почту, срок 24 часа. В базе лежит только хеш токена. Форма всегда отвечает «письмо отправлено» — иначе по ней можно было бы проверять, зарегистрирован ли человек.

Смены пароля из интерфейса нет — только сброс по почте. Для этого у людей должны быть настоящие адреса и должен быть настроен SMTP.

Версии и выкат

Одна версия — один выкат. Патч растёт при каждом деплое; минор 0.2.0 — когда меняется то, как люди работают; мажор 1.0.0 — когда выполнен критерий готовности из паспорта проекта.

Версия видна в правом нижнем углу на любом экране, включая вход. Открыли сервер, посмотрели в угол — сразу ясно, доехало обновление или нет. 

cd /opt/guildofcomfort
git pull origin claude/company-app-project-xxhilu
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml run --rm migrate
Состояние держат два тома: база и загруженные файлы. Всё остальное пересобирается из образа. Бэкап нужен именно с них — а в инструкции описан только pg_dump базы.
