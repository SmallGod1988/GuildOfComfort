### Что приложение умеет

Объекты → подпроекты → задачи по справочнику операций с техкартами;
складской учёт по объектам; табель с ролью бригадира и выгрузкой в Excel;
приватные взаиморасчёты; три роли с раздельными кабинетами.

Сверх исходного MVP сделано за август:

- **Загрузка книги КП**: `.xlsx` с телефона → дерево задач, веса по стоимости
  позиций, блоки работ и их очерёдность. 92 строки заводятся за один раз
- **Готовность снизу вверх** по весам из денег КП, а не по числу закрытых строк
- **Блоки работ** с графом очерёдности, порогом готовности предшественников
  и ручной причиной блокировки
- **Восстановление пароля** по ссылке на почту, срок 24 часа
- **Увольнение сотрудника** с закрытием доступа при первом же обращении
- **Загрузка картинок** с телефона в том Docker

## 3. Ближайший шаг

**Развернуть текущую ветку на сервере и загрузить книгу КП через браузер.**

Всё, что сделано за август, лежит только в репозитории — на проде этого нет.
Отстают 26 коммитов и **три миграции**: почта, дерево задач, блоки работ.

```bash
cd /opt/guildofcomfort
git pull origin claude/company-app-project-xxhilu
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml run --rm migrate
```

**Проверяемый результат:** на `158.255.0.71:3000` открывается «Загрузка КП»,
книга загружается, объект с 92 задачами и 15 блоками создан, готовность
показывает 0 %.

## 4. Чего я НЕ делаю

- **Не перехожу на NoSQL.** Схема стабильная, связей много, нужны транзакции.
  Для гибких полей хватит JSONB-колонки в Postgres
- **Не завожу вики внутри приложения** — отложено, документация живёт в `docs/`
- **Не пишу мобильное приложение** — телефонный сценарий закрывается браузером
- **Не делаю автоматический расчёт зарплаты** — только начисления и выплаты руками
- **Не делаю RLS на уровне Postgres** — авторизация на уровне приложения,
  обоснование в `README.md`

Известные пробелы, которые пока приняты:

- Нет смены пароля из интерфейса (только сброс по почте)
- Нет отказа от взятой задачи и возврата из статуса «Принята»
- Нет возврата материалов на склад — только новый приход
- Нет кабинета финансов у монтажника (данные в модели есть, экрана нет)
- Нет актов выполненных работ
- Почтовые уведомления (отчёты, расчётка, сообщения от админа) спроектированы,
  но не написаны

## Критерий готовности v1

книга КП загружена, монтажники отмечали объёмы с телефона по ходу работ,
табель за месяц выгружен в Excel без ручных правок, заказчик смотрел
готовность сам и не спрашивал статус в мессенджере.
